# ReadingFlow

Локальний десктопний застосунок: Electron + React + TypeScript + SQLite.
Сервер, обліковий запис та підключення до інтернету під час використання не потрібні.

## Запуск

Потрібні Node.js 22.12+ та npm. У терміналі в папці проєкту:

```powershell
npm install
npm start
```

Перед запуском збережіть зміни та закрийте базу в DB Browser, щоб уникнути блокування запису.

## База даних

Під час розробки використовується `readingflow.db` у корені проєкту.
Наявні записи зберігаються. Для нової бази таблиці створюються автоматично
зі скрипту `database/schema.sql`; початкові профіль і налаштування додаються один раз.
SQL-схема зберігається у Git, особиста база й журнали — ні.
База не включається до інсталятора.

У встановленій програмі окрема база створюється в Electron `userData`;
точний шлях показано внизу вікна. База розробки туди автоматично не переноситься.
Використано вбудований модуль `node:sqlite` замість запроєктованого в курсовій
`better-sqlite3`, тож окрема компіляція нативного модуля не потрібна.
Цю зміну технологічного рішення слід відобразити в курсовій.

## Перевірки та збірка

```powershell
npm run typecheck
npm run lint
npm run package
npm run make
```

`package` створює папку застосунку в `out`, `make` — дистрибутив для поточної платформи.
Кросплатформні збірки потрібно перевіряти на відповідних операційних системах.

## Каркас інтерфейсу

Під час першого запуску користувач створює локальний профіль: ім'я, один із шести
аватарів і денна ціль. Після збереження наступний запуск відкриває головну сторінку.
Світла й темна теми зберігаються у SQLite. Початкова тема відповідає системній.
Існуюча база версії 1 автоматично оновлюється до версії 2 без видалення книг;
початковий технічний профіль «Читач» не вважається завершеним знайомством.

`src/App.tsx` керує запуском і навігацією, `src/components` містить спільні
компоненти, `src/pages` — сторінки, `src/styles` — палітри та компонування.
`src/shared.ts` описує типи API, `src/preload.ts` — міст IPC,
`src/database.ts` — запити та міграції бази.

Сайдбар відкриває п'ять порожніх розділів. Блок користувача внизу сайдбара
інформаційний і не клікабельний. Функціональні екрани наповнюватимуться поступово.

## Основа роботи з книгами

Підключення SQLite та API читання й додавання книг залишені для наступного етапу.
Екран бібліотеки наразі замінений порожнім каркасом на прохання користувача.
Renderer ізольований, має лише типізований API через preload; довільні SQL-запити
з інтерфейсу не дозволені. Вхідні дані повторно перевіряються в основному процесі.

Таймер, редагування й видалення книг, нотатки, календар, статистика, мінітаймер,
нагадування та експорт ще потребують реалізації.
